# R004-测试标准细则-分层断言与门禁流程

> 角色：**本仓测试规则**。AGENTS 操作规则「写测试时」的细则，三层展开——**分层与目录**、**断言与命名**、**门禁与演进**。
> 依据：移植自 ohmyagents 同名细则（其三源对照研究：Command-Line Rust 书 2022 地基、2026 社区综述、microsoft/rust-guidelines `c1d2efc`）；rmux 闸门语境已换写为本仓真机对齐闸门 `OME_TEST_REAL`。本文事实性断言标六态溯源，标准见 `docs\guide\G002-研究标准细则-结构与六态标记.md`。

## 一、分层与目录

> 分层按官方三层；ome 的第四形态是真机对齐测试：`OME_TEST_REAL` 闸门下对照 `ohmyenv.ps1` 行为。

| 层 | 落点 | 测什么 | 约定 |
| --- | --- | --- | --- |
| 单元 | 源码同文件 `#[cfg(test)] mod tests`，`use super::*` | 私有 API、单函数边界、错误路径、不变量 | 正式构建不含测试代码 |
| 集成 | `tests\*.rs`，每文件独立 crate | 仅公开 API、模块协作、对外契约 | 不写 `#[cfg(test)]`；共享夹具放 `tests\common\mod.rs` 用 `mod common;` 引入 |
| 文档测试 | `///` 内 ```` ```rust ```` 代码块 | 公开 API 示例可编译可运行 | `cargo test --doc` 单独跑；lib 公开面少则暂不写 |
| 真机对齐 | `tests\*.rs` 内 `OME_TEST_REAL` 门控用例 | 与 `ohmyenv.ps1` 行为对照（status 三态、query 同 tag、daily 同判定） | 闸门不满足 skip 不失败；不写真实注册表、不动真实 EnvRoot |

- 能用集成覆盖就不用单元：集成不依赖内部结构，重构时更稳。[实证: rust-guidelines M-INTEGRATION-TESTS；书第 3 章同向]
- `tests\` 每个顶层 `.rs` 是独立 crate；`tests\common\mod.rs` 不会被当成独立测试目标。[经验: 官方 cargo 约定]
- ome 现状：`tests\` 已建 cli / install / golden / real / linux_install 五个集成目标；`tests\fixtures\tools.toml` 夹具、`tests\expected\` 黄金文件、`tests\common\mod.rs` 共享 helper 就绪。[实证: 2026-09-01 查本仓]

## 二、断言与命名

> 意图对应方法；期望值必须有独立来源。

### 1. 意图到方法

| 意图 | 方法 | ome 对应 |
| --- | --- | --- |
| 冒烟（活着即可） | 断退出码 0 | `ome --version`、`ome status`（沙盒） |
| 集成（用户方式整跑） | assert_cmd 跑二进制，断 stdout/stderr/退出码 | `ome pin`、`ome status`（临时 EnvRoot 沙盒喂 `tests\fixtures\tools.toml`） |
| 回归（改动不破旧） | 黄金文件全量重跑 | `tests\expected\` 黄金文件全量比对 stdout（pin 全量、status 三态；约定见二、4） |
| 验收（对照外部标准） | oracle 生成期望 | `ohmyenv.ps1` 的 status/query/daily 输出（真机对齐闸门） |
| 不变量（任意输入成立） | 属性测试 | 版本串解析、TOML 往返（后置） |
| 性能 | 基准工具，不进断言 | 目标外 |

### 2. 断言规则

1. **期望值来自独立来源**：规范、黄金文件、属性约束。不得用被测同款逻辑复述期望值，不得镜像实现分支——重言式测试按构造通过，纯噪声，AI 生成测试高发。[实证: rust-guidelines M-TAUTOLOGICAL-TESTS]
2. **只断稳定字段**：标记行、退出码、stderr 关键词；放过 pid、时间戳、机器差异（owner、列宽、目录大小）。[实证: 书第 14 章 Testing Underground]
3. **一个测试一件事**；失败信息能定位（panic 消息带原因与实际值）。[实证: rust-guidelines M-PANIC-MESSAGE]
4. **正例负例成对**：`success()` 与 `failure()` 对应写；无参数应失败并打用法是标准负例。[实证: 书第 1-2 章]
5. **错误路径必须覆盖**：空输入、缺文件、权限失败、超时，不只测 happy path。[经验: 三源共同原则]
6. **测试体错误传播**：`type TestResult = Result<(), Box<dyn std::error::Error>>`，用 `?` 代替 `unwrap`。[实证: 书第 2 章]
7. **输出无序时双侧 sort 后比对**（status 列表类）。[实证: 书第 7 章]

### 3. 命名

- 测试名写成可读规格：动词加条件加预期（如 `pin_writes_back_version_and_asset`）。[经验: 社区惯例]
- 期望失败的负例名带 `dies_` 前缀，`cargo test dies` 可过滤。[实证: 书第 2 章]
- 常量收敛：测试文件顶部 `const PRG` / 路径常量用全大写。[实证: 书第 3 章]
- 重复模式收进 helper（`run(args, expected)` 形态）。[实证: 书第 3、14 章]

### 4. expected 文件 oracle

> 多行、结构化输出的回归断言：期望整体冻结进 `tests\expected\` 文本文件，测试全量比对 stdout，比逐行 `contains` 更防回归且透明可审。依据 S002（书 p38-40 的 mk-outs.sh 模式）。

1. **何时用**：输出多行或带结构（status 三态对照、pin 全量列表），逐行 `contains` 会放过行序、空行与缺失行时，升格为黄金文件全量比对；单行冒烟与负例不必升格。[推断: S002 值得吸收第 1 条]
2. **目录约定**：`tests\expected\<名>.txt` 一测试一文件，进 git 可审；文件头以 `##` 起首行写来源注释（何时首跑、核对了什么契约、归一化说明），比对时由 helper 剥除（ome 自身组标题是单个 `#` 起首，与 `##` 不冲突）。[实证: 2026-09-01 tests\expected\pin.txt / status.txt]
3. **冻结纪律**：先跑一遍程序取输出形态，人工核对符合契约（R001 字段、key=value 输出纪律）后冻结；黄金文件变更必须走 diff 审查，不自动接受。[实证: M-TAUTOLOGICAL-TESTS 期望值独立来源要求]
4. **helper 用法**：`tests\common\mod.rs` 的 `run_ome(args, envs)` 跑二进制（自动注入 OME_CATALOG 夹具），`assert_stdout_eq_golden(name, &out, sandbox)` 读黄金文件全量比对 stdout。[实证: 2026-09-01 tests\common\mod.rs]
5. **归一化纪律**：输出含非确定内容（沙盒临时路径）才在比对前归一化，临时路径替换为 `<SANDBOX>` 占位符并在黄金文件头注释说明；路径分隔符统一归 `/` 是跨平台单 oracle 的取舍；归一化集中在 common helper，不在测试体散写。[实证: 2026-09-01 tests\common\mod.rs normalize]
6. **与 OME_TEST_REAL 闸门分工**：黄金文件是沙盒内离线回归，期望值冻结自本程序经人工核对的输出；闸门测试对照外部 oracle（ohmyenv.ps1 真机行为）。两者期望值来源不同，互补不替代。[推断: S002 oracle 分层]
7. **cfg 双平台期望**：出现实质跨平台输出差异（分隔符级别以上）时，启用双 oracle——`tests\expected\<名>.txt` 与 `<名>.windows.txt` 两份期望，测试按 `#[cfg(windows)]` 选文件；触发条件出现前不预先落地代码。[实证: 书 p164-165 `.windows` 双期望模式]

## 三、依赖与闸门

1. **测试依赖白名单**：`[dev-dependencies]` 只进 assert_cmd、predicates（按 crates.io 现版复核后引入）；rstest、insta、proptest 等各设触发条件（见第五节），不预先引入。[推断: AGENTS 写 Rust 规则的最少依赖原则对测试的适用]
2. **mock 策略**：ome 拿临时 EnvRoot 沙盒集成，不默认 mock；注册表 PATH 与外网下载不进沙盒路径，留给真机对齐闸门；时钟、熵源等非确定边界若进产品路径，留 trait 注入口。[推断: rust-guidelines M-MOCKABLE-SYSCALLS 与本仓沙盒策略的调和]
3. **真机对齐闸门**：依赖真实 `D:\ohmyenv`、用户 PATH 注册表、外网下载的测试由 `OME_TEST_REAL` 环境变量门控；未设置则 skip 并说明，不失败、不安装、不写真实注册表、不动真实 EnvRoot。[推断: ohmyagents 闸门模式延伸]
4. **测试设施 feature gate**：沙盒注入、下载桩、安全旁路收进单一 `test-util` feature；闸门 skip 不算旁路。[实证: rust-guidelines M-TEST-UTIL]
5. **环境夹具**：临时目录、临时 EnvRoot；测试自清理（删临时目录）。[经验: ohmyagents POC 同法]

## 四、门禁

> 最小集本地化；CI 化后按第五节扩展。

1. **本地门禁三件**：`cargo fmt --all -- --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test --locked`。
2. **锁文件**：Cargo.lock 入仓后测试跑 `--locked` 防依赖漂移。[经验: 社区门禁惯例]
3. **慢测**：下载类与真机对齐类不进默认路径；标 `#[ignore]` 或 `OME_TEST_REAL` 门控，默认反馈保持秒级。[实证: 书 biggie 分离原则]

## 五、演进路线

## 六、AI 协作自检

> 本仓为 AI 协作仓，写测试前过一遍。

1. 期望值是否来自独立来源？若来自「我刚写的实现」，停，换规范或黄金文件。[实证: M-TAUTOLOGICAL-TESTS 点名 Agent 高发]
2. 是否先复现再固化？bug 修复先写失败测试再改代码。[经验: TDD 红绿循环，书第 3 章]
3. 断言的是行为（公开输出）还是实现（内部结构）？内部重构不应炸测试。
4. 快照与黄金文件不自动接受；变更必须可审。[经验: 社区快照纪律]

## 七、与六态的衔接

- 测试绿是 `[实证]` 的最强依据：研究文档断言可引用测试名（如 `[实证: tests\cli.rs::dies_no_args 2026-08-31]`）。
- 真机对齐测试落地前后，研究文档里的实证标注不变来源；闸门测试只是让该实证可重复。
- 未落地的门禁项（nextest、CI）在研究文档保持 `[记忆]` 或 `[推断]`，不因写入本文升级。

## 八、验收自查

写完测试自查：

1. 分层落点正确（单元在 `#[cfg(test)]`、集成在 `tests\`、公开 API 不塞 `mod tests{}`）
2. 期望值有独立来源；无重言式断言
3. 断言只含稳定字段；正负例成对；错误路径有覆盖
4. 命名可读；负例带 `dies_`；重复收 helper
5. 真机依赖有 `OME_TEST_REAL` 闸门；测试自清理；临时物不残留
6. 黄金文件测试比对前归一化非确定内容；expected 文件带 `##` 来源注释并进 git
7. 本地门禁三件通过
