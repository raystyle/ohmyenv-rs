# R015：软件清单发布更新与播种标准

> 角色：现役标准。ome 软件清单（`catalog\tools.toml`）的**发布、更新**与**软件资产播种**三流程的唯一流程权威；字段与 pin 语义在 R001，跨仓协调与段域在 R014，签名方案研究在 S006，测试闸门在 R004 三.6。2026-09-10 定档（D32/D33/D34 收口后成文，D35）。

## 一、角色与信任链

| 角色 | 承担 |
| --- | --- |
| 仓库 `catalog\tools.toml` | 开发面唯一 pin 源与离线兜底源；入册走 R001 入册 checklist（catalog_lint 机检、seed.py --plan 域面 diff） |
| 云端 `ome/catalog/`（env.ohmygh.com） | 运行态权威：清单本体、`.sha256` 边车、`.minisig` 签名件三件套 |
| `.sha256` 边车 | 传输完整性锚（种子端自官方资产或清单自算即锚） |
| `.minisig` 签名 | 来源真实性锚（Ed25519；公钥内嵌 ome 二进制，当前 `FB93BFD3788C2316`；轮换走内嵌集合过渡） |
| 私钥 | 只在开发机 `~/.config/ome/` 与 GitHub Secret `CATALOG_SIGNING_KEY`，永不入仓 |

## 二、清单发布：仓库到云端

1. 开发改 `catalog\tools.toml`，过 R001 入册 checklist 与 catalog_lint 机检。
2. push main（seed-mirror 触发面：`catalog/**`、`.tools/catalog-sign/**`、流水自身）。
3. CI 签名步：缺 `CATALOG_SIGNING_KEY` 即失败，**不发布未签名清单**（红线）。
4. seed.py 幂等重灌云端三件套，并按 catalog pin 补种软件资产差集。
5. 发布验收：云端三件 HEAD 200；本机 `ome catalog sync` 验签落位 `signature=valid`。

## 三、清单更新：云端到端

| 通道 | 语义 |
| --- | --- |
| `ome catalog sync` | 显式刷新，不受 TTL 与 `OME_OFFLINE` 限制；也是修复通道 |
| TTL 自动刷新 | 仅用户数据副本；默认 24h（`OME_CATALOG_TTL` 可改，0 关；`OME_OFFLINE=1` 等效关）；单次 5s 探活加 `.last-sync` 退避标记 |
| 裸端自举 | 四级解析全 miss：镜像优先走同款三重门；镜像不可达官方 raw 兜底（未验签，WARN 如实告警） |

- **三重门（落位前缺一不可）**：边车 sha 锚比对、`Catalog::load` 解析、内嵌公钥验签；任一不过拒收。
- **落位纪律**：临时名随目标派生（`tools.toml.tmp` 与 `tools.toml.minisig.tmp`）；先清单后签名件。
- **加载前巡检**：invalid 阻断全部非 catalog 命令（含 self update，防被篡改面自我升级）；missing 仅用户数据副本告警；catalog 子命令整组豁免保自愈。
- **本地回写**：pin/update 改写即撤签名（内容已变，不留假凭证）；下次 sync 恢复。
- **升级 runbook**：跨版本 self update 后带一次 `ome catalog sync`（旧版孤儿签名为一次性迁移伤痕，0.3.0 起条件化撤签名防复发）。

## 四、软件播种：资产到云端

| 路线 | 触发 | 段域 |
| --- | --- | --- |
| A 自产 | push main、push v* tag、workflow_dispatch | main 灌 `ome/dev` 沙滚；v* tag 灌 `ome/stable` 正式（段名与 self update 通道同名，`ome/latest` 已退役） |
| B catalog | seed-mirror（每日加 catalog push） | 软件资产 `/<tool>/<version>/<asset>` 加边车；`ome/catalog/` 三件套 |

- 无 sha 不入镜（pending 队列）；边车自算即锚；rclone NO_CHECK_BUCKET 必带；Cache-Control 60s 加消费侧 `?v=`/`?t=` 击穿双保险。
- 消费侧：官方渠道优先、镜像回落仅当有锚（catalog pin 或 latest 边车）；selfupdate 分通道对应段。

## 五、管辖边界

2026-09-10 用户裁，两域分治：

| 域 | 管辖 | 内容 |
| --- | --- | --- |
| ome 自身 | ome 仓全权 | 代码与功能更新、发版（tag、CI、`ome/dev` 与 `ome/stable` 自产段播种）、二进制自更新（self update 三通道） |
| ome 所管软件 | 托管 omc | 清单发布与更新的运营（云端三件套的刷新节奏、端上同步编排）、软件资源播种与分发的运营；catalog 数据权威仍在 ome 仓（唯一 pin 源），ome 提供消费原语（install/query/status/catalog）与锚规范 |

承接形态由 omc 侧定：直接消费本仓 CI 维持的云端供给（零迁移），或接管签名与播种流水（需移转 `CATALOG_SIGNING_KEY` 与 `.tools/catalog-sign`）；承接期间本仓流水不撤，保供给连续。

## 六、例外与挂起

- 开发面（仓库 cwd 与 `OME_CATALOG` 指定面）不入签名巡检：信任自担，开发流程零干扰。
- 挂起：回滚与重放防护（清单内 generated_at 加单调 seq，拒收更旧，S006 候选 B）排 v0.3.x；`ome/latest` 旧段下架待用户明示。
