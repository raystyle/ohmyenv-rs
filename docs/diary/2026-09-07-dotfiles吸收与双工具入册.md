## 做了什么

1. **dotfiles 摸底**：仓概貌（Intel macOS 专用、deploy.sh 模块化、cli/manifest.tsv 的 Agent 友好栈 13 工具）、`lib\download.sh` 四段下载链（gh、api.github.com、aria2c、curl 依次回落，硬超时，镜像前缀，github web 停滞探测）、cargo rsproxy 与 go goproxy 镜像配置。
2. **吸收裁决**（用户）：首轮「暂只吸收模式」，旋即改裁「只加 zoxide，其余吸收学习 zsh starship sheldon 配置方式」，再追加「sheldon 也加」。
3. **zoxide 入册**：首版 pattern 带 v 前缀全不匹配，gh api 实证资产名不带 v（tag v0.10.0、资产 zoxide-0.10.0）后修正；win zip 根级 zoxide.exe 直中（dir=zoxide）；toolver 补正则后 install 幂等加 sha 回填加 deploy 全绿（Windows 本机闭环）。
4. **sheldon 入册**：上游无 Windows 资产也无 darwin-x86_64（0.8.5 实测仅 linux musl 三架构加 aarch64-darwin），Windows 走 platform_managed 空态（shellcheck 先例）；条目初版漏通用 repo 字段被解析报错抓出补上。
5. **WSL 双端验证**：self update 后 catalog 有条目但 pin 键缺（远端 main 未含本地回写），手动同步仓库 catalog 后 `ome pin` 双家解析绿（zoxide v0.10.0 linux musl、sheldon 0.8.5）；install 下载解压双就位（二进制可跑），状态回写被旧 ome 验版本步误拦（旧二进制无新 toolver 正则），新 dev 资产后自愈。
6. **S004 落档**：吸收裁决表、下载链四段模式（D08 输入）、配置栈学习、镜像对账（cargo rsproxy 与 go goproxy 均与 ome 现状一致）、intel mac 三应对（pin 末版、allow-compile、跳过）；INDEX/AGENTS/README 同步 43 工具。

## 自省

- **资产名前缀要逐家实证**：tag v0.10.0 不代表资产名带 v（zoxide 反例）；pattern 写完先 query --latest 实测再入库，首版想当然全不匹配。
- **替换脚本静默失败同 tail 坑族**：python replace 不带 assert 两处 old 串不精确静默没换（INDEX 的 S004 与 diary 行），靠输出核对抓回；批改必须 assert 命中或跑后核验，与 M006 同根因（工具链吃掉失败信号）。
- **验版本步依赖探测表**：新工具入册三件套是 catalog 条目、toolver 正则、（有需要的）平台字段族；漏正则的表现是「安装后未找到可执行文件或无法读取版本」误报，文件其实在。
